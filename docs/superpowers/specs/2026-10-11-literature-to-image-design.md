# 外国诗文意境图 Agent：产品设计草案

日期：2026-10-11。状态：供用户审阅的方案，尚未开始产品实现。

## 已确认的需求

- 输入以外国诗歌和文学散文为主，不按中国古诗审美设计。
- 当前成品是意境插画，不需要字幕和旁白；最初提到的视频留作后续扩展。
- 偏好冷色调、接近真实风景的画面，希望尽量减少合成感。
- Agent 根据文字自主选择画面氛围和画风。
- UI 界面简洁，操作简便。

## 产品目标

用户粘贴诗文，Agent 理解情绪、意象及其关系，选择适合的画面表达，生成并保存一张自然写实的意境图。用户可以用普通语言提出修改，Agent 在已有画面基础上继续创作。

成功的关键是文学情绪和画面氛围的对应，同时控制光线、材质、透视和细节的自然程度。不能承诺每次生成都无法被识别为合成图。

## 本方案采用的默认决定（并非用户已确认的要求）

- 先做个人使用、在本机浏览器访问的工具，使用现成云端模型 API。
- 支持外国文学原文和中文译文；第一轮以英语原文和中文译文验证，其他语言不作首版质量承诺。
- 首版输入限制为去除首尾空白后 1–8000 个 Unicode 字符，超限明确提示，不静默截断。
- 每次默认生成 1 张图；默认横幅 3:2，允许用户改为其他已验证的比例。
- 自动完成理解、画面设计和出图，构想不需要用户逐项确认。
- 默认自然写实、偏冷色、低至中等饱和度；原文明示的季节、天气、色彩和情绪优先于默认偏好。
- 只在用户修改或主动查看时展示简短的创作依据，避免把专业提示词变成必填表单。
- 图片尺寸、模型和服务商在样例试验后确定，不在计划阶段承诺某个供应商的效果或单价。

## 文学到画面的工作流程

1. 接收原文、可选标题与作者，保留换行；不自动搜索或补写作者背景。
2. 理解文本：提取核心情绪、重要意象、场景线索以及抽象表达。原文证据与创作补充分开记录；允许多义性，不将解释说成唯一含义。
3. 设计画面：确定视觉主体、空间、构图、天气、光线、色调及写实程度；必要时以空景、倒影、距离和光影表达抽象情绪，避免把每个比喻都画成实体。
4. 生成图片：将结构化画面设计转成图像模型提示词，调用已验证的图像服务。
5. 有限质检：检查关键意象、情绪方向、自然程度和明显画面缺陷；记录问题。首版只提示，不因自动评分循环付费重画。
6. 保存和反馈：保存原文、理解结果、提示词、模型信息、图片及版本。用户可提出“光线更柔和”“去掉人物”等自然语言修改。

### 视觉决策规则

- “冷色”不等于给所有作品覆盖蓝色滤镜；优先通过阴天、薄雾、阴影色、自然环境建立冷感。
- 不默认增加人物、建筑、宗教标志或特定国家地标。文本没有相关线索时，采用克制的画面表达。
- 原文明示对象必须保留或说明取舍；抽象意象允许视觉转译，且说明是创作选择。
- 优先检查水面、枝叶、建筑边缘、地平线、人物比例以及光源一致性。
- 原文中的命令式语言属于文学内容，不得被当作系统指令或调用工具的授权。

## 首版功能与边界

包含：文本输入、自动出图、状态展示、简短创作说明、自然语言修改、作品历史、原图下载、有限质检、调用统计。

后续：参考图偏好、系列作品一致性、长篇分段、静态图片生成短视频。

当前范围外：模型训练、视频生成、字幕、旁白、音乐、多用户账号及支付系统、自动发布到外部平台。

## 界面与操作设计

用户已确认“简洁、操作简便”；以下布局与配色是本方案的建议。

- 首页采用单页布局，一个宽大的诗文输入框和一个醒目的“生成图片”按钮。标题、作者和图片比例放在默认折叠的“更多选项”中，均无需填写即可生成。
- 生成中显示简短状态，例如“正在理解文字”“正在生成画面”，保留已输入的文字；提交后立即禁用重复提交，失败或完成后恢复可用。不显示未经验证的完成百分比。
- 生成完成后，图片成为页面视觉重点；操作区保留“下载原图”和“调整画面”。点击调整后出现自然语言输入框和“应用修改”按钮。
- 创作依据、历史版本和调用记录按需展开；作品历史由顶部“我的作品”入口访问，避免常驻复杂侧栏。
- 建议采用灰白背景、清晰的文字、充足留白和克制的蓝灰色强调色；原图不添加界面滤镜。首版不使用装饰性背景动画。
- 桌面和手机都可完成输入、生成、修改和下载；窄屏按输入、状态、图片、操作顺序排列，按钮有文字标签，键盘可操作。
- API 密钥在一次性后端配置中提供，不在每次生成流程里询问。模型选择、采样参数和提示词编辑不作为首版用户必填内容。

界面验收：使用默认设置时，粘贴文字后只需点击一次“生成图片”即可开始创作；原图下载只需一次点击；修改只需填写一句话并提交。空输入和失败提示出现在相关操作附近，已有文字和作品保留。

## 技术设计

建议 Python + FastAPI 作为后端，React + TypeScript 作为前端，SQLite 保存项目和任务，本地文件目录保存图片。选型是本方案的建议，待实际开发时锁定兼容版本。

采用显式工作流：分析 → 画面设计 → 生成 → 评估 → 保存。不引入多 Agent 系统或复杂编排框架作为首版依赖。文学分析模型、图像模型和可选视觉评估模型分别通过适配器接入；首版只实现一套可用的供应商适配器。

图像供应商必须通过实际账号验证：生成、已有图像编辑、目标比例、错误反馈及调用统计。Gemini 图像 API 是可验证候选，其官方文档提供生成和图像编辑能力，但尚未针对本项目样例测试。若最终选用的接口不支持参考图编辑，只能明确提供“按原文重新生成”，不能承诺保留原图。

生成任务必须持久化。单独 worker 顺序处理 SQLite 中的任务，首版最多 1 个活动任务；界面轮询状态。任务状态为 queued / running / succeeded / failed / needs_review。API 进程重启不丢失 queued 任务；worker 中断后的 running 任务标记 needs_review，禁止自动重新发起可能重复计费的图像请求。

图像请求超时或响应不明确时，保留任务并提示核查；服务商支持请求查询或幂等机制时优先使用。可确认尚未提交的临时失败最多重试 1 次；付费图像请求不进行盲目重试。用户主动重试生成新任务并保留关联。

API 密钥仅放后端环境变量，不进入浏览器、日志或导出的作品资料。每个任务保存模型标识、提示词版本、调用次数、耗时、usage（可取得时）；没有可靠价格配置时展示调用量，不编造费用。

数据对象：Artwork（原文和当前版本）、Interpretation（情绪/意象/证据/创作补充）、VisualBrief（画面设计）、Job（调用状态）、ImageVersion（提示词/图片/父版本/修改请求/评估）。

## 验证与验收

建立 12 段用户可合法使用的诗文样本：至少 6 段英语原文、6 段中文译文；覆盖孤独、静谧、悲伤、温暖、明亮与抽象表达。样本、参考意象和期望情绪由人工标注，避免只用 Agent 自己评分。

用户逐张按 1–5 分评价：原文关联、情绪氛围、自然程度、个人喜好。拟定首版目标：12 个样本中至少 9 个在前两项均达到 4 分；至少 9 个自然程度达到 4 分。此为调试目标，需用户确认，不是模型质量保证。

功能验收：有效输入可出图和下载；修改生成关联的新版本；历史记录完整；失败原因可见；重启后待处理任务仍存在；响应不明确时不重复计费提交；所有超限和空输入明确反馈。

先用人工评估验证产品价值，再完善界面。模型测试记录实际调用次数、耗时和试验费用，不设未经验证的成本或响应时间承诺。

## 时间与后续

以一位开发者、账号可用、调用现成 API 为假设，初版估计 10–14 个工作日；模型效果调试和供应商接入问题可能延长周期。

视频阶段从选定图片出发，为风、雾、水面等设计克制的运动；待静态图片的审美表现稳定后单独制定计划。当前不实施视频接口。
